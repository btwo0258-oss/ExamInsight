# ExamInsight V2 产品规格

> 状态：产品边界冻结稿  
> 适用版本：公开 Beta  
> 本文只定义产品行为，不代表当前代码已经实现。数据结构见 [DATA_MODEL.md](./DATA_MODEL.md) 和 [PHYSICAL_SCHEMA.md](./PHYSICAL_SCHEMA.md)，接口与状态机见 [API_AND_STATE_MACHINES.md](./API_AND_STATE_MACHINES.md)，实施与验收见 [MIGRATION_AND_ACCEPTANCE.md](./MIGRATION_AND_ACCEPTANCE.md)。

## 1. 产品定位

ExamInsight 面向有明确考试日期和目标、愿意自主学习的学生，将其课程资料、考试范围、真题和个人基础转化为可执行、可验证、可动态调整的考试冲刺计划。

V2 首个适配器只处理通用知识型笔试，重点覆盖：

- 大学课程期末考试。
- 以知识理解、记忆和客观/短文本作答为主的证书考试。
- 四六级、考公等考试中的通用文本知识学习场景，但不在 V2 Beta 中建设听力、长作文、申论等专项系统。

核心价值不是“生成很多学习资料”，而是形成可追踪的提分闭环：

```text
学习依据 → 考试范围 → 基础诊断 → 差距分析 → 学习计划
       → 每日执行 → 作答反馈 → 错题复习 → 掌握度更新 → 调整计划
```

## 2. 目标用户与核心场景

### 2.1 目标用户

- 年满 18 周岁、自主决定学习目标的学生。
- 有明确考试或阶段考核日期。
- 已拥有课程资料、讲义、大纲、教材摘录或真题中的至少一种；没有资料时也可以手工确认考试范围。
- 希望在有限时间内知道“学什么、先学什么、今天做什么、做得怎么样”。

### 2.2 核心场景

1. 考试前数周：分析课程资料，制定完整冲刺计划。
2. 考试前数日：快速识别高优先级薄弱点，生成可执行任务。
3. 学习过程中：完成任务、练习与错题复习，动态更新掌握度。
4. 已完成今日计划后：选择强化、额外练习，或提前执行符合条件的下一日任务。
5. 资料或考试安排变化：用户提出修改，AI 生成候选方案，用户确认后生效。

## 3. V2 Beta 边界

### 3.1 必须提供

- 邮箱注册、登录、验证、找回密码及必要的反滥用保护。
- 个人资料库、知识库和资料版本管理。
- 普通 AI 对话及四个通用能力入口。
- 学习项目创建和唯一的一条准备流程。
- 资料解析、范围确认、诊断、差距分析和计划生成。
- 用户手工编辑计划、用自然语言要求 AI 修改计划、版本确认。
- 练习、测验、模拟试卷、作答、评分、解析和引用。
- 按日任务执行、有效学习时间热力图、提前学习。
- 错题本、订正、立即变式和间隔复习。
- 学习助教、受约束的项目上下文和操作确认。
- AI 调用记录、质量评测、Token/成本与用户额度记账。
- 用户行为、学习行为、质量、成本、安全和性能监控。
- 数据导出、回收站、账户删除与数据保留规则。
- 管理员读取用户数据必须经过独立 MFA、双人审批、限时只读授权和逐次审计。

### 3.2 明确不做

- 公共资料市场、资料售卖、公开社区。
- 听力材料生成和播放器专项训练。
- 长作文、申论等专用批改体系。
- 真人教师或机构管理后台。
- 基于真实姓名、学校、学号或手机号的实名体系。
- 在未确认的情况下由 AI 自动修改计划、删除资料或消费较大额度。
- 把用户上传内容默认用于模型训练或产品评测。

知识库是个人资料的命名集合，不是第二份资料存储。加入知识库只创建关联并读取资料当前可用版本，不复制文件、不重复解析；永久删除知识库或移除关联都不能删除个人资料。知识库进入回收站时保留关联，恢复发生重名时由用户明确改名。学习项目仍以用户确认的版本快照为准，不随知识库变化自动漂移。

## 4. 信息架构与入口

### 4.1 新对话首页

固定展示四个通用快捷能力：

1. 生成思维导图。
2. 生成 PPT。
3. 生成图片。
4. 生成文案。

快捷卡只负责设置能力意图和推荐提示词，进入的仍是普通对话。能力必须由统一能力注册表控制：

- `HIDDEN`：不展示。
- `BETA`：只向测试人群展示并标记 Beta。
- `AVAILABLE`：正式展示。
- 后端不可用或权限不足时，前端不能单独显示为可用。

### 4.2 智能学习首页

固定展示四个与考试冲刺直接相关的能力：

1. 制定学习计划。
2. 分析学习资料。
3. 分析试卷或真题。
4. 完成基础诊断。

无项目时，点击任一卡片均进入“创建学习项目”，并携带入口意图；已有项目时，先让用户选择项目或新建项目。卡片不伪装成可以脱离项目直接完成的功能。

### 4.3 学习项目内导航

```text
项目总览
今日学习
学习计划
学习资源
错题本
学习助教
项目设置
```

准备阶段仍使用同一项目路由，但显示准备步骤，不混入普通对话页面。

## 5. 唯一项目创建与准备流程

### 5.1 创建项目弹窗

创建弹窗只收集：

- 项目名称：必填，可由用户修改，默认根据考试目标建议名称。
- 项目图标：必选，提供默认值。
- 图标颜色：必选，提供默认值。
- 基础知识库：可选，最多关联一个。

创建时不要求填写全部考试信息，也不触发完整计划生成。

### 5.2 项目准备页

准备页固定为六步，只有当前步骤展开，已完成步骤折叠为摘要：

```text
1. 确认考试目标
2. 确认学习依据
3. 确认考试范围
4. 完成基础诊断
5. 确认差距分析与计划草稿
6. 确认资源生成配置
```

不得增加第二条并行创建流程。

### 5.3 第一步：确认考试目标

用户确认：

- 考试名称。
- 考试日期及所在时区。
- 目标分数、目标等级或“通过”。
- 可学习日期、每周可用日和每日时间预算。
- 不可学习日期。

系统校验：

- 考试日期必须晚于当前时间。
- 总可用时间过少时不阻止创建，但明确提示计划风险。
- 日期变化不会直接覆盖当前计划，而是触发重新分析候选版本。

### 5.4 第二步：确认学习依据

用户可以：

- 使用创建项目时关联的基础知识库。
- 从个人资料库选择资料，选择时可进入知识库查看。
- 上传新资料。
- 解除某份资料与当前项目的关系。

“关联知识库”的意义是提供一个可复用的资料集合入口；真正参与项目分析的是用户最终确认的资料版本快照。

确认后建立项目学习依据版本：

```text
知识库/个人资料库/新上传资料
→ 选择具体资料
→ 等待资料解析
→ 用户确认本次学习依据
→ 锁定 asset_version + parse_result
```

知识库后续增加、删除、移动或更新资料，均不得静默改变已经确认的项目依据。

### 5.5 第三步：确认考试范围

系统只基于已确认的学习依据生成范围建议，并为每个范围节点展示来源引用和置信度。

用户可以：

- 添加、删除、合并、拆分或调整范围节点。
- 标记重点、次重点和不考内容。
- 上传或填写考试大纲作为额外证据。
- 处理不同资料之间的范围冲突。

“确认考试范围”指确认最终要纳入诊断和计划的知识范围，不等于确认某个文件的全部内容都会考。

### 5.6 第四步：基础诊断

默认建议诊断，但允许跳过。跳过时：

- 掌握度保持 `UNKNOWN`。
- 计划基于范围优先级、资料证据和用户自评生成。
- UI 明确标记计划置信度较低，并保留稍后补做诊断的入口。

诊断题必须覆盖范围中的代表性概念，并经过题目质量硬校验。诊断完成后产生：

- 范围内掌握度估计。
- 每个结论的证据和置信度。
- 薄弱点、未知点和优先级。

### 5.7 第五步：差距分析与计划草稿

差距分析综合：

- 目标与考试日期。
- 可学习时间。
- 已确认范围及其优先级。
- 诊断和历史作答证据。
- 用户偏好与自评。

生成计划时遵循：

- 总时间预算默认使用 85%，保留 15% 缓冲。
- 普通任务建议 15–45 分钟。
- 每日核心任务不超过 4 个。
- 临近考试时避免安排低优先级全新内容。
- 每项任务说明“为什么安排、覆盖什么、完成标准是什么”。

用户必须能够：

- 手工编辑未执行的任务。
- 调整日期、时长和顺序。
- 用自然语言要求 AI 修改。
- 比较当前版本和候选版本。
- 确认或放弃候选计划。

只有用户确认后，计划才成为当前执行版本。

### 5.8 第六步：资源生成配置

系统先展示计划所需资源清单，而不是立即全部生成。用户按资源类型确认：

- 哪些资源必须生成。
- 哪些资源按需生成。
- 是否生成模拟试卷。
- 题量、难度和可接受的额度估算。
- 默认滚动生成未来两个有效学习日，或一次性生成所有可预测资源。

错题变式、自适应练习等依赖未来作答的数据，不进入“一次性全部生成”。

## 6. 资源生成与 UI 反馈

生成期间不得显示空白页。页面展示：

- 已确认的计划摘要和资源清单骨架。
- 当前阶段：排队、检索依据、生成、校验、保存。
- 单项资源的状态和可重试操作。
- 已完成资源立即可用，失败资源不影响其他资源。
- 长任务允许离开页面，返回后从服务端恢复状态。

所有进度以服务端异步任务为准，客户端不得伪造百分比或直接写入“已完成”。

## 7. 每日学习与提前学习

### 7.1 今日学习页

按照以下顺序提供建议，但不强制用户逐项执行：

```text
今日正式任务
→ 到期的间隔复习
→ 今日新错题强化
→ 可提前执行的下一日任务
→ 已有额外练习
→ 用户确认额度后生成新练习
```

用户可以跳过强化，直接进入满足以下条件的下一日任务：

- 前置依赖已经完成。
- 所需资源已经可用，或能够在进入前生成。
- 任务没有被计划版本替换或取消。

提前完成后保留原计划日期，并记录实际完成日期和“提前完成”来源，不把后续所有日期自动前移。

### 7.2 学习时间热力图

只展示按日期聚合的有效学习时间。有效时间来自：

- 用户主动开始的学习会话。
- 页面保持活跃且持续发送受信任心跳。
- 作答、翻页、阅读进度等行为能够证明仍在学习。

长时间无操作、后台标签页、网络断连、重复心跳和客户端自行上报的任意秒数不计入有效时间。

## 8. 错题本闭环

错题本是错题处理的统一入口，不另建一套“错题强化”孤立功能。

```text
答错或部分正确
→ 建立/更新错题条目
→ 展示正确答案、解析和依据
→ 用户确认错误原因并完成订正
→ 生成并完成立即变式题
→ 安排 D1、D3、D7 间隔复习
→ 达到正确率、置信度和次数门槛后标记已掌握
```

仅阅读解析、收藏或填写订正笔记不直接提高掌握度。无效题被撤销后，其评分、掌握度证据和错题状态必须重新计算。

## 9. 普通对话与学习助教

### 9.1 共用部分

- 会话、分支和不可变消息。
- 流式响应。
- 附件、引用、模型调用、额度和错误处理。
- 编辑消息创建新分支，重新生成创建回答变体。

### 9.2 不同部分

普通对话只组装：

- 当前分支的对话历史。
- 用户本轮附件。
- 用户明确选择的知识库。
- 所选通用能力的工具和提示模板。

学习助教额外组装：

- 当前学习项目、目标和时区。
- 已锁定的学习依据与考试范围。
- 当前计划、今日任务和所处任务。
- 历史作答、错题和掌握度摘要。
- 当前页面和用户意图所需的最小上下文。

不得把整个项目所有文件、所有消息和全部数据库记录无差别塞入模型。

### 9.3 AI 操作边界

AI 可以直接：

- 解释知识点、题目和计划原因。
- 搜索项目依据并给出引用。
- 草拟计划修改、资源需求和复习建议。

AI 不可以直接：

- 删除或替换资料。
- 确认考试范围。
- 切换当前计划版本。
- 修改考试日期或目标。
- 扣除超出提示额度的资源。

此类操作先生成待确认操作卡片，用户点击确认后由业务服务执行。

## 10. 题目与生成质量

题目必须保存生成依据、引用和生成版本。发布到用户前至少通过：

- 结构和字段完整性校验。
- 正确答案可判定性校验。
- 题干与选项一致性校验。
- 重复和近重复检测。
- 引用存在且能够支持答案。
- 范围、难度和题型符合生成要求。
- 答案不得随题目列表接口泄漏。

硬校验失败的题目不得进入诊断、练习或模拟试卷。模型不确定时必须标记不确定或拒绝生成，不能用流畅文本掩盖证据不足。

## 11. 主题与组件规范

- 延用统一主题 Store 和根节点 `data-theme`。
- 新页面只使用语义化颜色、间距、圆角、阴影和字体 Token。
- 禁止组件内分别维护一套浅色/深色硬编码。
- 项目步骤卡、任务卡、状态标签、空状态、错误状态、骨架屏、待确认操作卡必须成为共用组件。
- 新组件必须验证浅色、深色、窄屏、长文本和错误状态。

## 12. 公开 Beta 成功指标

### 12.1 产品漏斗

```text
注册验证
→ 创建项目
→ 确认学习依据
→ 确认考试范围
→ 完成/跳过诊断
→ 确认计划
→ 开始首个任务
→ 完成首日学习
→ 7 日内继续学习
```

### 12.2 学习指标

- 计划确认率、首任务开始率和任务完成率。
- 有效学习天数和有效学习时间。
- 诊断到后测的掌握度变化，但不得把模型估计包装成真实提分。
- 错题订正率、立即变式完成率和间隔复习完成率。
- 计划被用户修改的比例及修改原因。

### 12.3 AI 质量与成本

- 题目硬校验通过率和人工抽检正确率。
- 引用覆盖率和引用有效率。
- 计划被直接确认、手工修改、AI 重生成的比例。
- 每个完成学习项目、计划和有效题目的模型成本。
- 超时、失败、重试、降级和用户取消比例。

## 13. 冻结规则与可配置项

### 13.1 冻结规则

- 产品定位与唯一学习工作流。
- 资料、知识库、项目依据和生成资源之间的关系。
- 计划版本确认、滚动生成、错题闭环和学习时间口径。
- 普通对话与学习助教的上下文隔离。
- AI 只能提出高影响修改，不能绕过用户确认。
- 核心业务使用关系结构，不以 JSON 代替领域模型。
- 导出、账户删除、跨存储清理、墓碑防复活和管理员受控访问边界。

### 13.2 可配置项

- 邮件、验证码、对象存储和模型供应商。
- 模型路由及具体模型名称。
- 免费额度、资源价格和并发限制。
- 诊断题量、资源预生成天数和部分推荐阈值。
- Beta 人群和能力发布状态。

可配置项必须有默认值、边界、审计记录和故障降级，不得改变上述冻结规则。
