## 1. 最终目的和边界

交付一个以新对话、个人资料库为主体的 Agent + RAG 应用。用户能上传并管理资料，关联知识库后与 AI 对话，获得可追溯引用，并按明确要求生成文档、思维导图、PPT 和图片。

前端重点是完整的交互：即时进入对话、流式展示、动态高度虚拟列表、消息版本、附件、导航、统一阅读器和草稿编辑。后端使用 Spring Boot、Spring AI 和现有业务服务，负责受控工具执行、权限、数据持久化和失败处理。

保持以下约束，不在实施时自行扩展：

- 产品仅有新对话、资料库；登录注册是基础能力。不恢复智能学习，也不因此重做侧边栏外观。
- 不迁移到 Python、LangChain 或 LangGraph；不把更换框架当成完成产品功能。
- 模型可以选择允许的工具，后端负责权限、参数、范围、次数、超时和执行结果校验。
- 普通问答不强制检索；RAG 仅检索当前对话明确关联的一个知识库和最多 20 个直接附件，不搜索整个个人资料库。
- 知识库选择面板默认“无”，列出现有知识库，可新建。关联知识库时，新上传附件自动加入该知识库，同时进入个人资料库；不复制底层文件。
- 桌面使用回形针附件入口；移动端保留“+”展开图片/文件入口。上传状态在输入区展示，发送后附件保存在对应消息中。
- AI 回复不使用头像或气泡；用户消息保留右侧深色气泡且无头像。回复内容与输入框等宽，操作图标为浅灰色。
- 用户消息：复制、编辑；AI 消息：复制、重新生成、朗读。没有赞踩。消息版本切换和 SegmentPanel 分段导航是两套不同功能。
- 四张卡：文档、思维导图、PPT、图片。缺少主题时先收集要求，点击卡片不凭空生成。
- 文档在对话内编辑；导图和 PPT 在独立页面编辑。确认前可编辑，确认后只读；图片生成成功自动入库，其他三类确认后入库。
- AI 生成文件进入资料库，不因此自动进入事实检索索引；现有上传资料和 AI 生成物的来源规则需要前后端一致。
- 统一预览外壳、按格式选择渲染器。没有“询问此文件”入口。安全文件超过预览预算时只提供下载；危险文件不能借下载降级绕过安全检查。
- 资料回收站保留 30 天。开发使用受控本地存储，正式部署使用 OSS；MySQL 保存业务记录和文件引用。
- RAG 质量报告、可视化管理后台暂缓。当前不新增联网搜索、MySQL MCP 或让模型直接访问数据库。

## 7. 第七部分：联调、上线条件和清理

### 7.1 以四条用户路径验证，不靠功能清单打勾

允许验证后按以下路径运行；有失败就记录具体步骤和原因，不标整个产品完成：

1. 登录 → 上传 → 建知识库 → 关联提问 → 真实流式回答 → 点击引用。
2. 编辑问题/重新生成 → 切换版本 → SegmentPanel 定位 → 刷新恢复。
3. 四类生成物分别走完编辑、确认、入库、下载、预览。
4. 长对话、断网、模型失败、索引失败、移动端和暗色主题；失败时有可解释状态，恢复后可重试，不造假成功结果。

本轮不再扩展第五条独立路径，不制作 RAG 质量报告页面或其他管理后台。对话置顶/分页/重命名/删除、资料回收恢复和跨用户权限仍属于已有实现的回归项，只在上述路径触发时验证，不拆成新的产品范围。

检查使用仓库已有测试与构建命令，优先覆盖修改链路。付费模型调用采用小样本，先明确调用范围；不无限重试烧 Token。本轮只执行本地构建、单元测试和浏览器契约测试，未主动调用真实供应商模型、STT 或 TTS。

本轮第七部分已完成前端联调修复：移动端附件入口接入现有 `ImageCaptureUploader`，统一为“+”胶囊并提供上传附件、上传照片、拍照；正文点击会关闭菜单。会话列表 API 增加空响应归一化，避免启动阶段因异常响应直接触发 `undefined.filter`；SegmentPanel 不再误伤 900px 以下的平板/窄桌面，只在手机宽度隐藏。新增当前契约 E2E，覆盖详情消息、复制/编辑/重新生成、版本切换和 SegmentPanel 导航；新增统一资源预览 E2E，覆盖 Markdown 阅读器外壳、代码块渲染和超预算下载降级；新增附件契约 E2E，验证选择知识库、上传附件卡片和自动关联；上述 Chromium 测试均通过。桌面/移动附件交互与“首页发送后立即跳转并流式显示”也通过。旧认证/资料库断言已按当前 V2 契约更新；旧独立 PPT 工作区和旧消息 DOM 视觉套件已明确跳过，当前等价能力由 V2 契约测试覆盖。
